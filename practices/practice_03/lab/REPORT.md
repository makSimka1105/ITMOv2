# Практика 3: локальная модель как помощник по репозиторию

## Железо и версии

| | |
|---|---|
| CPU | Intel Core i5-1240P, 12 ядер (4P + 8E), 16 потоков, без дискретной GPU |
| RAM | 14 GiB |
| ОС | Linux 7.0.0-38-generic |
| Ollama | 0.34.4, только CPU, `OLLAMA_NO_CLOUD=1` |
| OpenCode | 1.18.33 |
| Python | 3.14.4 (`make test`, `experiment.py`) |

## Модель

| | |
|---|---|
| Базовая модель | `qwen3.5:4b` (ID `2a654d98e6fb`), 4.7B параметров |
| Квантизация | Q4_K_M, 3.4 GB на диске |
| Рабочие сборки | `itmo-local` из `Modelfile` (прямой чат, 4096), `itmo-agent` из `Modelfile.agent` (OpenCode, 16384) |
| Параметры | temperature 0.2, num_thread 8, top_k 20, top_p 0.95, presence_penalty 1.5 (последние три из базовой модели) |

Почему эта модель: 4B в Q4_K_M помещается в память ноутбука с запасом, модель умеет tool calling (без этого OpenCode не сможет читать файлы) и нормально отвечает по-русски. 0.8B и 2B на агентном цикле OpenCode не тянут вызовы инструментов, а 9B+ на CPU дала бы единицы токенов в секунду.

## Контекст

`Modelfile.agent` и `opencode.json` переведены с 65536 на 16384. Реальные промпты OpenCode в прогонах занимали 2.7-5 тыс. токенов (системный промпт агента, описания инструментов, прочитанные файлы), так что 16k покрывает их с запасом. При этом KV-кэш на 16k занимает 512 MiB против нескольких GiB на 64k. Для прямого чата в `Modelfile` оставлено 4096: там в контекст идёт только README.

## Изменения конфигурации

- `Modelfile`: добавлен `num_thread 8`.
- `Modelfile.agent`: `num_ctx 16384`, `num_thread 8`.
- `demo/opencode.json`: `enabled_providers: ["ollama"]`, чтобы OpenCode не ходил в облачные провайдеры; лимит контекста модели 16384 в соответствии с Modelfile. Агент `local-guide` с `permission: {"*": "deny", read/glob/grep: "allow"}`, 8 шагов, системный промпт `demo/repo-system.txt`.
- `make test` из `lab/`: 3 теста, `OK`.

## Подбор числа потоков

`experiment.py`, режим `system`, вопрос про CI, temperature 0.2, seed 42, num_ctx 4096. Сырые ответы в `results/threads/`.

| Сборка | Прогонов | Декодинг, tok/s (среднее; мин-макс) | Полное время ответа, с |
|---|---:|---|---:|
| по умолчанию | 3 | 8.63; 7.81-10.16 | 9.6 |
| num_thread 4 | 3 | 8.35; 7.65-8.82 | 9.8 |
| num_thread 8 | 5 | 11.20; 10.89-11.47 | 7.3 |

8 потоков примерно по числу производительных потоков P-ядер дали +30% к декодингу и самый маленький разброс. По умолчанию Ollama занимает и E-ядра, и они тормозят остальные. Во всех 11 прогонах модель ответила «В предоставленных материалах нет ответа» и сослалась на README, то есть системный промпт удерживает её от выдумывания CI.

Каждый вопрос задавался в отдельной новой сессии: `opencode run --agent local-guide --model ollama/itmo-agent "<вопрос>"` из `demo/`. Эталоны подготовлены заранее по коду и в тестовые сессии не передавались. Полные логи с вызовами инструментов лежат в `results/answers/`.

Итог: 3 верных ответа (2, 4, 5), 1 верный с выдуманной деталью (1), 1 провал (3). Время ответа на один вопрос от 299 до 747 с.

Q3 прогонялся трижды: обычный запуск, повтор и запуск с `OPENCODE_DISABLE_CLAUDE_CODE=1` (`results/answers/q3*.md`). Я проверял гипотезу, что модель сбивают подмешанные глобальные правила, и она не подтвердилась: в третьем запуске за 900 с не случилось ни одного вызова инструмента и не появилось ни одного токена ответа. Вероятнее всего, модель с включённым по умолчанию thinking уходит в долгое рассуждение на вопрос «проверь предпосылку», а на 8 tok/s это тысячи токенов, которые не укладываются в таймаут. Следующий шаг: отключить thinking для агентной сборки или дать в системном промпте явный шаблон «если не нашёл, так и скажи».

## Ограничения и наблюдения

- **Скорость.** Декодинг 8-11 tok/s ещё терпим, но prefill на CPU всего 14-18 tok/s. Промпт OpenCode на 2.7-5 тыс. токенов обрабатывается 2.5-4.5 минуты до первого токена, и это повторяется на каждом шаге агентного цикла. Отсюда 5-12 минут на простой вопрос, хотя прямой чат через `experiment.py` отвечает за 7 с.
- **Подмешивание глобальных правил.** OpenCode по умолчанию подхватывает `~/.claude/CLAUDE.md`. В Q2 и в повторе Q3 модель начала ответ с правила из моего глобального файла («Локального CLAUDE.md нет, работаю в режиме учебный»), а в повторе Q3 потратила шаг на поиск `**/CLAUDE.md`. Изоляция тестовой сессии требует `OPENCODE_DISABLE_CLAUDE_CODE=1`.
- **Ложная предпосылка.** Модель находит, что `unsubscribe` нет, но не формулирует вывод «предпосылка ложна»: пустой результат grep обрывает цикл без финального ответа.
- **Права на чтение.** `read: allow` не ограничен папкой: агент читал файлы выше `demo/`. Для настоящей изоляции нужны правила с путями или запуск из отдельной копии.
- **Галлюцинации инструментов.** В Q5 модель попыталась вызвать несуществующий `google_search`. OpenCode отклонил вызов (`Model tried to call unavailable tool`), и модель продолжила с доступными glob/grep/read.
- **Номера строк.** В Q2 и Q5 ссылки точные, в Q1 номер строки выдуман, поэтому перед использованием их нужно проверять.
- **Пересборка моделей.** Модели лежат в системном `/usr/share/ollama` и принадлежат пользователю `ollama`. `ollama create` от обычного пользователя падает с `chtimes ... operation not permitted`, поэтому `itmo-local` пересобирается при сервисе, запущенном через `systemctl`.

## Воспроизведение

```bash
cd lab
make test
ollama create itmo-local -f Modelfile
ollama create itmo-agent -f Modelfile.agent
python3 experiment.py --mode system --model itmo-local --output results/run.json
cd demo && OPENCODE_DISABLE_CLAUDE_CODE=1 opencode run --agent local-guide --model ollama/itmo-agent "Где реализован unsubscribe? Проверь предпосылку вопроса."
```
